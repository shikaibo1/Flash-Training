# 后端结构与数据约定

## 分层

HTTP 路由 → 类型校验 → 独立业务服务 → 仓库/事务协议 → SQLite 实现。

`app/api/` 只处理请求、服务调用和响应；不引用数据库、仓库或模型客户端。`app/application/` 分别处理技能、练习、进度和历史统计，无 SQL 和 SQLite/SDK/HTTP 依赖。`app/domain/` 定义数据类型、业务规则和依赖协议。

SQL 存放于 `app/infrastructure/repositories/`；连接、迁移和管理命令中的管理 SQL 属于基础设施。AI 通过 `app/infrastructure/ai.py` 注入，任务说明与输出校验集中在 `app/application/content.py`。`create_app(settings, ai)` 可注入测试配置和替代模型，不需要真实密钥即可验证业务。

用例通过 `UnitOfWorkFactory.read()/write()` 明确事务边界。一次写操作中的所有仓库共用一个连接，由事务实现统一提交/回滚，仓库自身不提交。读事务启用 SQLite `query_only`，误写会直接失败。模型调用发生在事务之外。

所有 HTTP 路由均声明响应模型，OpenAPI 显示实际结构。新的题目、评估、技能和进度使用明确类型；可变参数使用限定为 JSON 值的映射。只有历史评估快照和历史记录扩展字段保留兼容结构，新增评分仍须通过严格校验。详细目录、职责和开发步骤见 [架构说明](架构说明.md)。

数据库采用 SQLite，适用于本机和当前项目规模，无需安装额外数据库服务。使用外键、唯一约束、分数范围约束、索引、WAL 和写事务。将来迁移 PostgreSQL 时需要调整连接、DDL 和仓库实现；目前不宣称支持 PostgreSQL。

## 表结构

| 表 | 用途 |
| --- | --- |
| `users` | 学习者标识 |
| `skills` | 技能、出题/评分提示词、启用状态和默认参数 |
| `atomic_skills` | 原子技能定义 |
| `skill_atoms` | 技能与原子技能的多对多关系及顺序 |
| `practice_sessions` | 完整题目、技能配置快照、会话状态 |
| `practice_attempts` | 用户答案与已成功校验的评估结果 |
| `practice_records` | 面向历史回放的记录，与会话一对一 |
| `user_atomic_scores` | 最近一次原子技能得分，注明来源 |
| `mastery_events` | 每次练习表现和掌握度变化的可追溯事件 |
| `user_skill_profiles` | 迁入的旧用户档案 |
| `legacy_imports` | 原始 JSON 完整快照及校验摘要 |
| `migration_reports` | 一次性迁移标记、数量与异常说明 |

身份、关联、状态和分数为独立列，使用数据库约束。题目快照、模型评语和可变参数保留为 JSON 列；不将所有内容塞进一个文件或一个总 JSON 字段。

`PRAGMA user_version=1` 标识第一版数据库结构。未来新增表/列应增加版本并编写升级迁移，不能直接修改已部署版本的 DDL。

## 数据迁移

首次启动或执行 `python -m app.manage migrate` 时：

1. 读取 `data/*.json` 和旧重复目录 `backend/data/practice_records.json`。
2. 在 `data/backups/<时间与随机标识>/` 备份原文件；损坏 JSON 会中止迁移，不会静默清空。
3. 在单个事务中导入数据、关系和历史。任一步失败则整体回滚。
4. 相同内容的记录去重；同 ID 的不同内容保留并重新分配 ID。找不到定义的历史技能创建为停用条目。
5. 保存迁移报告和源文件完整快照。再次启动只读取迁移标记，不再从 JSON 更新数据库。

原 JSON 文件不删除、不回写。迁移后应通过接口改技能，直接编辑 JSON 不会改变线上数据。若需要从另一份历史资料再次导入，应编写显式的新迁移，不要删除迁移标记。

此次实际迁入 14 个技能条目（其中 3 个仅用于历史关联）、8 个原子技能、26 条技能关联、12 个历史会话、7 次历史作答、21 条回放记录。已有 11 个可用技能继续显示在页面中。

原系统曾把 0–10 得分传入 0–1 掌握度接口。迁移时对历史事件中大于 1 的表现值除以 10，再按新规则重算掌握度；假设和处理结果写入迁移报告。原始值完整保留在 `legacy_imports` 和备份中。旧评分若曾来自占位结果，迁移不会将其追认成真实 AI 评估，也无法据此恢复真实学习表现。

## 练习一致性

- `/start` 生成并保存完整题目，前端显示同一份题目；刷新页面可恢复未完成会话。
- `/submit` 根据保存的题目和技能配置快照评估，不重新生成题目。
- 模型请求在写事务之外执行，避免网络等待长期锁住数据库。
- 评估成功后，在一个事务中写入作答、回放记录、原子得分和掌握度。
- 模型失败或结果校验失败返回错误，保留会话供重试，不保存分数或更新掌握度。
- 重复/并发提交同一会话只落一份结果。并发请求可能触发两次模型调用，但不会写两次记录；同一答案重试返回已保存结果，不同答案返回 409，要求创建新练习。
- 默认参数与用户参数合并后保存到会话，出题与评分使用同一份有效参数，后续编辑技能配置不会改变这次练习。
- 会话恢复接口同时返回已完成的评估与答案，可恢复“服务端成功但浏览器没有收到响应”的结果。前端按会话保存答题草稿，浏览器存储不可用时不会让成功请求被误判为失败。
- 新历史记录保存真实原子分数和名称；旧历史没有这些字段时，页面明确显示“未保存分项评分”，不随机补分。
- 技能移除和历史记录移除采用软删除，保留学习依据。隐藏回放记录不会回滚既有掌握度。

## 分数尺度

| 数据 | 范围 |
| --- | --- |
| 模型总分、原子技能得分 | 0–10 |
| 历史回放与前端展示分数 | 0–100 |
| 学习表现、掌握度 | 0–1 |

掌握度暂用透明的指数移动平均：`新值 = 0.7 × 旧值 + 0.3 × 本次表现`，初始值为 0。它是启发式指标，不是经过训练与校准的知识追踪模型，不宣称能准确预测考试表现。自评接口注明 `manual` 来源，自评原子得分不自动更新掌握度。

## 主要接口

接口文档：http://127.0.0.1:8001/docs

| 方法与路径 | 功能 |
| --- | --- |
| `GET /api/health` | 数据库状态、模型是否配置；不返回密钥 |
| `GET /api/v1/skills` | 包含停用技能的技能列表 |
| `POST /api/v1/skills` | 手动创建技能，不调用 AI |
| `PATCH /api/v1/skills/{id}` | 修改技能与原子关联 |
| `DELETE /api/v1/skills/{id}` | 移除技能并保留历史 |
| `GET /api/v1/atomic/skills` | 原子技能列表 |
| `POST /api/v1/atomic/skills` | 手动创建原子技能 |
| `POST /api/v1/practice/create_custom_skill` | AI 生成技能配置与具体原子技能；整体成功才保存 |
| `POST /api/v1/practice/start` | 生成并保存练习会话 |
| `GET /api/v1/practice/sessions/{id}?user_id=...` | 恢复会话 |
| `POST /api/v1/practice/submit` | 评估并原子保存 |
| `GET /api/practice/records/{user_id}` | 回放记录 |
| `DELETE /api/practice/record/{id}?user_id=...` | 隐藏指定用户的回放记录 |
| `GET /api/v1/knowledge-tracing/mastery/all/{user_id}` | 掌握度 |

为现有页面保留了 `/api/skills`、`/api/v1/practice/skills` 等兼容路径。旧客户端直接上传分数的 `/api/practice/record`、`/api/user/skill/update` 返回 410，避免客户端填分与服务端评估混用。原先已停用的录音/语音接口没有恢复。

## 管理与备份

在 `backend/` 目录运行：

```powershell
python -m app.manage inspect
python -m app.manage backup data/backups/manual.sqlite3
python -m unittest discover -s tests -v
```

备份命令使用 SQLite 在线备份 API，适用于服务运行中；目标文件必须不存在。恢复时先停止后端，保留当前数据库备份，再用备份文件替换配置指向的数据库。不要在服务运行中直接复制主库文件而遗漏 WAL。

本地工具暂不提供登录、权限角色和云端部署。接口中的 `user_id` 是数据分组，不是认证凭据。需要多人联网使用时，应先补认证、服务端用户身份、权限与独立部署配置。
